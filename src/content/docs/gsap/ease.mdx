多數人第一次用 GSAP 的 `ease`，是從別人的程式碼裡複製一串 `"power2.out"` 過來，
覺得好像確實比較順，然後就再也沒動過它。

問題出在 `ease` 的名字。它聽起來像一個形容詞 —— 順一點、彈一點、Q 一點 ——
於是選 ease 變成一件憑感覺的事。但它其實是一個**函式**：

```js
ease(0) === 0   // 動畫開始
ease(1) === 1   // 動畫結束
```

中間那段，就是它全部的內容。

## 你其實在指定一條曲線

`gsap.to()` 每一幀都會問同一個問題：**現在時間過了 30%，那動作該完成幾 %？**

`ease` 就是回答這個問題的函式。橫軸是時間，縱軸是進度，把答案畫出來就是一條曲線。

下面這個面板畫的就是那條曲線，右邊的方塊吃的是同一次求值 ——
**曲線的斜率就是方塊的速度**。斜率陡的地方跑得快，平的地方幾乎不動。

先把方向從 `out` 換成 `in`，看曲線怎麼翻過來：
`out` 是一開始就衝、尾巴收得慢，`in` 反過來。

然後把次方從 2 拉到 4。曲線的彎折越來越靠近尾端 —— 那就是「更劇烈的減速」
長什麼樣子。它不是更順，是更誇張。

## `out` 幾乎永遠是對的

如果只想記一件事，記這個：**UI 動畫預設用 `out`。**

理由不在美學而在感知。`out` 的前半段斜率最陡，也就是說**動作在最初幾十毫秒
就已經完成大半**。讀者按下按鈕、東西立刻大幅移動，感覺是「反應很快」；
剩下那段慢慢收尾的時間，人眼只當作「它停下來了」。

`in` 則相反 —— 一開始幾乎不動。同樣的 0.3 秒，`in` 感覺起來明顯比較鈍。

把上面的面板切到 `in` 再切回 `out`，注意的不是曲線，是**方塊剛開始動的那一瞬間**。

## 超過終點的那一族

`power` / `sine` / `expo` / `circ` 都乖乖待在 0 到 1 之間。
另外兩族不是：

<EaseLab family="back" direction="out" />

`back` 會**衝過頭再退回來** —— 曲線跑到 1 以上的那一段就是超出的部分。
把 overshoot 從 1.7 拉到 5，看曲線頂端越拱越高。

這在 UI 上是「有彈性」的來源，但代價是動畫變長、而且超出的位置可能撞到旁邊的元素。
`back.out(1.2)` 通常就夠了，1.7 是 GSAP 的預設值。

<EaseLab family="elastic" direction="out" />

`elastic` 更誇張，它會**來回穿越終點好幾次**。曲線上那幾個上下起伏就是擺盪。

- `amplitude` 是第一次衝過頭的幅度
- `period` 是擺盪的疏密 —— 調小，震得又快又碎

`elastic` 幾乎不該用在 UI 上（讀者會等它停），但用在「東西掉進來」這類
一次性的入場動畫很有效。

## 帶走那一串

面板上那串 `power2.out` 是可以直接複製的。拖到滿意之後：

```js
gsap.to(".card", {
  y: 0,
  duration: 0.4,
  ease: "back.out(1.4)", // ← 貼上來的那一串
});
```

**`duration` 與 `ease` 是兩件無關的事**，這也是上面的面板刻意沒有 duration 滑桿的原因 ——
曲線的橫軸是「進度」不是「秒」。同一條 `power2.out`，0.2 秒是俐落，2 秒是拖沓，
但它們是同一條曲線。先選曲線，再調時間。

## 一個對照組

最後把家族切到 `none`：

<EaseLab family="none" />

一條直線，等速。它是唯一看起來像機器的選項 —— 現實裡沒有東西是這樣移動的，
所有物體都要花時間加速與減速。這就是為什麼加上 ease 會「比較順」：
不是因為它比較慢，是因為它比較像真的。
