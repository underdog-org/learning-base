---
title: 捲動動畫的三種心智模型
description: ScrollTrigger 不是一個功能，是三種不同的東西。
order: 1
---

多數 ScrollTrigger 的教學會直接給你一段設定，然後說「這樣就會有捲動動畫」。
問題是當效果不如預期時，你不知道該調哪一個參數，因為你不知道它究竟在做什麼。

實際上捲動動畫有三種截然不同的模型，混淆它們是絕大多數問題的來源。

## 模型一：觸發

動畫在捲動到某個位置時**被啟動**，之後就按自己的時間播放，與捲動無關。

```js
gsap.to(".card", {
  y: 0,
  opacity: 1,
  duration: 0.6,
  scrollTrigger: {
    trigger: ".card",
    start: "top 80%",
  },
});
```

關鍵是這裡沒有 `scrub`。捲動只負責「按下播放鍵」，
按下之後動畫用自己的 `duration` 跑完。

這個模型適合入場動畫。使用者往下捲，元素浮現，即使他停下來，動畫仍會完成。

## 模型二：綁定

動畫進度**直接等於**捲動進度。使用者往回捲，動畫就往回播。

```js
gsap.to(".hero", {
  scale: 1.4,
  scrollTrigger: {
    trigger: ".hero",
    start: "top top",
    end: "bottom top",
    scrub: true,
  },
});
```

加上 `scrub` 之後，`duration` 就失去意義了——時間軸的長度由 `start` 到 `end`
這段捲動距離決定。這是新手最常困惑的地方：設了 `duration: 2` 卻毫無效果。

`scrub: 1` 與 `scrub: true` 的差別是前者加入 1 秒的追趕延遲，
讓動畫不會與捲動完全同步，手感更順。

## 模型三：釘選

元素在捲動時**停在原地**，而頁面繼續捲動，騰出的距離用來播放動畫。

```js
ScrollTrigger.create({
  trigger: ".section",
  start: "top top",
  end: "+=1200",
  pin: true,
});
```

`pin` 會改變版面——GSAP 會插入一個佔位元素來維持捲動高度。
這是三種模型中唯一會影響 DOM 結構的，因此也最容易與既有的 CSS 佈局衝突。

### 常見的衝突

祖先元素上的 `overflow: hidden` 或 `transform` 會讓 `position: fixed` 失效，
而 `pin` 依賴它。如果釘選沒有作用，第一個要檢查的就是這個。

## 如何選擇

| 你要的效果 | 模型 | 關鍵設定 |
| --- | --- | --- |
| 元素浮現、卡片依序進場 | 觸發 | 不加 `scrub` |
| 進度條、視差、逐格展開 | 綁定 | `scrub: 1` |
| 停留一段距離講完一件事 | 釘選 | `pin: true` + `end: "+="` |

先確定要哪一種，再去查參數。反過來做——先看參數表再決定效果——
是大部分挫折的來源。
